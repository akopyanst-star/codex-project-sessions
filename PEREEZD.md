# Переезд с Claude Code на Codex

Инструкция для Codex. Человеку достаточно открыть VS Code с установленным расширением OpenAI Codex и написать в чат одну строку:

```
Прочитай https://github.com/akopyanst-star/codex-project-sessions/blob/main/PEREEZD.md и выполни переезд по шагам.
```

Дальше Codex всё сделает сам и будет спрашивать на развилках.

**Где проверено.** Составлено и опробовано на Windows. На Mac, скорее всего, тоже сработает (Codex сам подставит пути), но не тестировалось. Если пробуете на Mac или что-то пошло не так - напишите в [Issues](https://github.com/akopyanst-star/codex-project-sessions/issues), инструкцию поправим.

---

## Для Codex: как выполнять

Ты помогаешь человеку перенести настройки Claude Code в Codex. Человек может не быть программистом: пиши ему просто, по-русски, без терминов без пояснения.

**Правила на всё время работы:**

- Только КОПИРУЙ. Ничего не удаляй и не перемещай: настройки Claude должны остаться как были.
- Никогда не открывай целиком файлы `.env`, `auth.json`, `.credentials.json` и не выводи ключи, пароли, токены.
- Если файл с таким именем уже есть - не перезаписывай, а спроси.
- `~` значит домашняя папка: на Windows `C:\Users\<имя>`, на Mac `/Users/<имя>`.
- Перед каждым шагом с изменениями покажи, что сделаешь, и дождись «да».

### Шаг 1. Разведка (ничего не меняешь)

Найди и покажи таблицей: что нашёл, сколько штук, куда предлагаешь перенести.

| Что | Где искать у Claude |
|---|---|
| Общие инструкции | `~/.claude/CLAUDE.md` |
| Инструкции проектов | `CLAUDE.md` в папках проектов (спроси, где лежат проекты; подсказка - список папок в `~/.claude/projects/`) |
| Скиллы | `~/.claude/skills/`, `.claude/skills/` в проектах |
| Команды (`/имя`) | `~/.claude/commands/`, `.claude/commands/` в проектах |
| Субагенты | `~/.claude/agents/`, `.claude/agents/` в проектах |
| MCP-серверы | `.mcp.json` в проектах, раздел `mcpServers` в `~/.claude.json` |
| Хуки | раздел `hooks` в `~/.claude/settings.json` и `.claude/settings.json` проектов |
| Память | `~/.claude/projects/*/memory/` |
| История чатов | файлы `*.jsonl` в `~/.claude/projects/*/` |

### Шаг 2. Инструкции

- `~/.claude/CLAUDE.md` -> скопировать в `~/.codex/AGENTS.md`.
- Каждый `CLAUDE.md` проекта -> скопировать рядом как `AGENTS.md` в той же папке.
- Если в тексте есть ссылки вида `@путь/к/файлу` - замени на обычную фразу «прочитай файл путь/к/файлу».
- Упоминания инструментов Claude (`Task`, `TodoWrite`, субагенты по имени) замени на обычные слова или убери, если без них смысл не теряется.

### Шаг 3. Скиллы, команды, субагенты

- Личные скиллы -> `~/.agents/skills/<имя>/` (папка целиком: `SKILL.md`, `scripts/`, `references/`).
- Скиллы проекта -> `.agents/skills/<имя>/` в том же проекте.
- Каждую команду и каждого субагента переделай в скилл: папка + `SKILL.md`, в начале поля `name` и `description` (по описанию Codex решает, когда включать навык).
- Проверь, что Codex видит навыки: перечисли их человеку.

### Шаг 4. MCP-серверы

- Перенеси каждый в `~/.codex/config.toml`, раздел `[mcp_servers.<имя>]` (поля `command`, `args`, `env`). Можно командой `codex mcp add`, если она есть.
- Ключи и токены НЕ переписывай в открытую. Оставь ссылку на переменную окружения и скажи человеку, какие переменные завести.
- Перед переносом скажи, какие серверы требуют ключей.

### Шаг 5. Память и история

- Память Claude -> собери в `memory.md` в каждом проекте, в `AGENTS.md` проекта добавь строку «перед работой прочитай memory.md».
- Чаты как живые чаты перенести нельзя - форматы разные. Вместо этого для каждого проекта прочитай последние 5 чатов и сделай `history-claude.md`: о чём говорили, что решили, что осталось недоделанным. Без паролей, ключей, телефонов и других личных данных.

### Шаг 6. Хуки

Не переноси автоматически. Перечисли человеку каждый хук простыми словами: когда срабатывает и что делает. Предложи, как повторить важные: правилом в `AGENTS.md` или скриптом, который Codex запускает сам.

### Шаг 7. Запущенные программы

Для каждого проекта, где есть код, найди, как он запускается (`package.json`, `requirements.txt`, `README`, `docker-compose`), и запиши короткий раздел «Как запустить» в `AGENTS.md` проекта. Ничего не запускай без спроса.

### Шаг 8. Дополнение для VS Code (по желанию)

Спроси человека, хочет ли он панель со списком чатов проекта и лимитами. Если да:

1. Скачай `.vsix` со страницы https://github.com/akopyanst-star/codex-project-sessions/releases (последняя версия).
2. Установи: `code --install-extension <путь к файлу> --force`. Если команда `code` не найдена (часто на Mac) - объясни ручной путь: VS Code -> Extensions -> «...» -> `Install from VSIX...`.
3. Скажи выполнить `Developer: Reload Window`. Дополнение само спросит про правку официального расширения - не включай за человека.

### Шаг 9. Отчёт

Таблица: что перенёс, что не получилось, что человеку сделать руками (завести переменные с ключами, перезапустить VS Code, проверить навыки).
